# 현황판 UI/UX 개선 플랜: Herdr의 chute mod를 손쓸 일 중심으로 다시 짠다

> 작성일 2026-11-17. 플랜 에이전트가 쓴 설계다. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 1. 사용자가 풀려는 문제

사용자는 레이아웃 `main-chute`의 오른쪽 패널 열(폭 약 368px)에서 files 아래에 chute 현황판(`mod/chute/`)을 띄워 쓴다. 사용자의 요청은 "chute mods herdr uiux 더 개선하고 싶어"였고, 오케스트레이터가 낸 제안 1~8을 "전부 적용으로 하고, 그런데 ui를 세련되게" 하라고 했다.

지금 화면(2026-11-17 캡처)의 문제는 다음과 같다.

1. 저장소마다 오늘 통계 6칸이 화면 대부분을 차지한다. 손쓸 정보(진행 중 batch, 멈춤, 승인 대기)는 밀려난다.
2. "42분 28초 검증 시간"은 하루 합계인데 한 번 걸린 시간처럼 읽힌다.
3. 머지 뒤 검사 칸은 큰 `—`와 작은 "검사 중 e2e"뿐이다. 시작 시각, 평소 걸리는 시간, 마지막 통과 커밋이 보이지 않는다.
4. 저장소 이름이 `Soochol/vallyt…`로 잘린다. 늘 같은 배지("허브 이 PC", "에이전트 신뢰")가 자리를 차지한다.
5. 최근에 머지된 일이 보이지 않는다.
6. 알림이 패널 안에만 있다. 패널을 보고 있지 않으면 멈춤을 놓친다.

요청에 적힌 것이다. 그대로 따른다.

| 항목 | 결정 |

| 디자인 | 좁은 패널(약 368px)에서 깔끔하게 읽히게 한다. Herdr 기본 mod(files, agents, tabs)와 같은 시각 언어(테마 색 토큰, 글꼴, 간격, 라운드)를 쓰고 색을 코드에 박지 않는다. 다크와 라이트 테마 모두에서 읽혀야 한다 |

## 3. 데이터가 있는지 확인한 결과

`tests/fixtures/status-full.json`, `src/model.rs`, `src/cmd/status.rs`, Herdr의 `herdr.d.ts`, `gpui-kit.d.ts`, `AGENTS.md`(`~/.config/herdr-app/`)를 읽고 확인했다.

| 제안 | 필요한 것 | 지금 있는가 |
|---|---|---|
| 1 | 단계 이름 | `batch.step`이 있다 |
| 1 | 전체 단계 수(m)와 지금 순번(n) | 없다. `Batch`에는 지금 단계 이름만 있다. 단계 목록은 `chute.toml`에 있고, `paths`로 건너뛰는 단계가 있어서 batch마다 다르다 |
| 2 | 묶인 PR과 제목 | `batch.prs`와 `queue`의 `in_batch` 항목 제목이 있다 |
| 2 | 경과 시간 | `batch.started_ms`가 있다 |
| 2 | 평소 시간 | `recent[].seconds`(최근 batch 10개의 걸린 시간)의 중앙값으로 mod에서 계산한다. 본체를 고치지 않는다 |
| 3 | 오늘 통계 | `today`가 있다 |
| 4 | 마지막 통과, 지금 검사, 실패 정보 | `post_verify.last_green`(커밋, 시각), `post_verify.run`(대상 커밋, 단계, 시작 시각, 범인 찾기 여부), `post_verify.red`(원인 PR, 시험, 로그, 보고서, 마지막 통과)가 모두 있다 |
| 5 | 최근 머지된 PR 번호, 시각 | `recent[].merged`(번호)와 `finished_ms`가 있다 |
| 5 | 머지된 PR의 제목 | 없다. 머지되면 큐 항목이 지워지고, history의 `merged` 사건에도 제목이 없다 |
| 5 | 반송 횟수 | `status`에는 없다. history의 `bounced` 사건을 세면 나온다 |
| 6 | toast | Herdr `notify({title, body, level, action})`가 있다 |
| 6 | 사이드바 space 옆 배지 | **mod가 쓸 수 있는 방법이 없다.** `setBadge`는 macOS Dock 아이콘의 배지이고 다른 OS는 무시한다. space 목록 배지를 mod가 정하는 API는 없다. 사이드바의 `↓2` 표시는 Herdr가 자체로 그리는 것이다 |
| 7 | 허브가 다른 PC인지, 신뢰 모드 | `hub.local`, `approval`이 있다. tooltip은 gpui-kit의 `.tooltip(text)`가 있다 |
| 8 | 로그·보고서 경로 | `last_failure.report`, `blocked.log`, `post_verify.red.log`/`report`가 있다. 파일을 보여 줄 Herdr 방법: files mod는 밖에서 파일을 열라는 명령을 받지 않는다. 대신 `openOverlay({kind: "window", mod, props})`로 창을 띄우고 그 안에서 `readTextFile(path, {on})`과 읽기 전용 `Editor`로 보여 줄 수 있다 |
| 5 | GitHub PR 열기 | gpui-kit의 `cx.open_url(url)`이 있다(http/https만 받는다) |
| 숫자 | tabular 숫자 | gpui-kit에 글꼴 기능(tnum) 설정이 보이지 않는다. 숫자 칸은 오른쪽 정렬과 최소 폭으로 흔들림을 줄인다 |

그래서 chute 본체에 필드 두 개를 더하는 작업을 따로 둔다(5절 작업 1).

- `batch.steps`: 이번 검증 회차가 돌릴 단계 이름 목록. "n/m단계"에 필요하다. mod가 `chute.toml`을 직접 읽으면 `paths`로 건너뛰는 단계와 기준 커밋의 설정을 맞출 수 없고, "데이터는 status에서만 읽는다"는 제약에도 어긋난다.
- `recent_merged`: 최근 머지된 PR 5건(번호, 제목, batch, 머지 시각, 반송 횟수). 제목은 머지 순간에만 알 수 있으므로 history의 `merged` 사건에 `title`을 더해 남긴다. mod가 `chute events --json`을 따로 부르면 poll마다 프로세스가 하나 더 뜨고 그래도 제목은 없다.

두 필드는 더하는 것이고 있는 필드의 이름과 뜻은 바꾸지 않는다(저장소 규칙). 옛 chute를 쓰는 원격 허브에서는 두 필드가 없으므로 mod는 없을 때도 그린다(단계 수 없이 단계 이름만, 최근 머지는 `recent`의 번호만).

## 4. 디자인 방향

### 4.1 정보 위계

한 저장소 안의 순서는 "지금 손쓸 일 → 지금 돌아가는 일 → 지나간 일 → 통계"다.

1. 머리: 저장소 이름(굵게)과, 허브가 다른 PC일 때만 `허브 desk` 칩. 이름에 마우스를 올리면 전체 slug와 승인 방식("에이전트 신뢰" 또는 "사람 확인")이 tooltip으로 나온다.
2. 상태 한 줄: 색 점 + 한 문장. 저장소의 지금 상태를 한 줄로 말한다(4.2).
3. 경고 카드: 멈춤, 머지 뒤 검사 실패, 데몬 꺼짐, 경고. 테두리를 실패 색으로 둔다.
4. 사람 차례: 승인 대기, 사람 차례 카드(지금의 카드와 버튼을 정리해 유지).
5. 지금 batch: PR 목록, 단계, 진행 막대.
6. 대기: 번호 줄. 한 줄에 순번, PR, 제목, 오른쪽 끝에 표시 하나(CI 대기, 급함, `#12 뒤`).
7. 반송: 한 줄 요약(PR, 제목, 사유). 누르면 보고서를 연다. 에이전트와 재시도는 둘째 줄에 작게.
8. 머지 뒤 검사: 마지막 통과와 지금 검사를 두 줄로. 실패는 3번 경고 카드로 올라간다.
9. 최근 머지: 5줄.
10. 오늘: 한 줄, 누르면 펼친다.

비어 있는 구역은 그리지 않는다. 저장소가 둘 이상이면 저장소 사이에 구분선을 둔다.

### 4.2 상태 한 줄

위에서부터 처음 맞는 것 하나만 보인다.

| 순서 | 조건 | 문구 | 색(의미) |
|---|---|---|---|
| 1 | 허브에 닿지 않는다 | 허브에 닿지 않는다 | 실패 |
| 2 | `blocked`가 있다 | 멈춤 · 기준 커밋이 검증에 실패했다 | 실패 |
| 3 | `post_verify.red`가 있다 | 머지 뒤 검사 실패 · e2e | 실패 |
| 4 | 데몬이 꺼져 있다 | 데몬이 꺼져 있다 | 실패 |
| 5 | 승인 대기나 사람 차례가 있다 | 사람 차례 2건 | 사람 차례 |
| 6 | batch가 있다 | 검증 중 · test 2/3단계 (단계 수가 없으면 `검증 중 · test`, PC 자리를 기다리면 `PC 자리 기다리는 중`) | 진행 |
| 7 | 대기열이 있다 | 대기 3건 | 진행보다 옅은 색 |
| 8 | 그 밖 | 정상 · 대기 없음 | 정상 |

색은 테마 토큰으로만 고른다. 진행은 `working`, 사람 차례는 `blocked`, 정상은 `done`, 실패는 지금 코드가 쓰는 빨강 토큰(`ansi1`)이다. 의미와 토큰을 잇는 함수는 하나만 두고 모든 곳이 그것을 쓴다.

### 4.3 목업

폭 약 368px 패널 기준이다. `●`는 상태 색 점, `▰▱`는 진행 막대, `›`는 누르면 열린다는 표시다. 실제 화면은 테마 색과 Herdr 글꼴로 그리고, 상자 선은 1px 테두리와 둥근 모서리(8px)다.

**A. 바쁜 저장소** (batch 진행, 승인 대기, 대기열)

**D. 오늘을 펼쳤을 때**

```
│  오늘  머지 9 · 반송 1 · 중앙값 4분        ⌄  │
│        flaky                          0     │
│        batch                         10     │

│    ssh: connect to host desk port 22: …     │  ← muted, 줄바꿈
│    5초마다 다시 읽는다                         │
```

```
│          등록된 저장소가 없다                  │
│    저장소에서 `chute init`을 실행한다.         │
```

읽기 실패(`chute`를 실행할 수 없다, JSON이 아니다)는 실패 색 테두리 카드 하나에 제목, 첫 줄 오류, 안내를 둔다. 지금 문구를 유지한다.

**F. 로그·보고서 창** (제안 8)

```
┌ pr-15/2.md ─────────────────── [ 닫기 ] ┐
│ (읽기 전용 코드 보기, 줄 번호)           │
│ # #15 반송 보고서                       │
│ ...                                     │
└─────────────────────────────────────────┘
```

창(`openOverlay` window, key `chute-file`)은 같은 키로 다시 열면 그 자리에서 내용을 바꾼다. 허브가 다른 PC면 그 PC에서 읽는다.

**G. toast** (제안 6)

```
┌──────────────────────────────────────┐
│ ⛔ chute · vallythevally              │
│ 머지 뒤 검사가 실패했다 · e2e (#12)   │
└──────────────────────────────────────┘
```

### 4.4 시각 언어

- 색은 모두 `theme()` 토큰이다. 코드에 `#rrggbb`나 `rgb(`를 쓰지 않는다.
- 크기와 간격은 Herdr 기본 mod(files, agents, tabs)의 값을 읽어 맞춘다. 구역 제목은 작고 옅게(11px, `muted`), 본문 13px, 보조 12px, 경로 11px.
- 카드는 사람 차례와 경고에만 쓴다. 나머지 구역은 카드 없이 줄로 둔다. 좁은 폭에서 상자가 겹겹이 쌓이지 않게 하기 위해서다.
- 누르는 줄은 마우스를 올리면 `hover` 배경이 깔리고 오른쪽 끝에 `›`가 있다.
- 칩은 상태를 말할 때만 쓴다. 늘 같은 값(허브 이 PC, 에이전트 신뢰)은 칩으로 두지 않는다.

## 5. 스스로 정한 결정과 그 이유

| 결정 | 이유 |
|---|---|
| chute 본체에 `batch.steps`와 `recent_merged`를 더한다(작업 1) | 3절. 단계 수와 머지된 PR 제목은 지금 어느 출력에도 없다. mod가 `chute.toml`이나 `gh`를 직접 읽으면 데이터 출처 제약을 어기고 poll 비용이 는다 |
| 머지된 PR 제목은 history `merged` 사건에 `title`로 남긴다 | 머지되면 큐 항목이 지워져서 그 뒤에는 제목을 얻을 곳이 없다. 옛 history 줄에는 제목이 없으므로 그 PR은 번호만 보인다 |
| 반송 횟수는 history의 `bounced` 사건을 세어 `recent_merged`에 넣는다 | 큐 항목의 `attempts`는 머지와 함께 사라진다. history는 이미 status가 읽는다 |
| 평소 시간은 mod에서 `recent[].seconds`의 중앙값으로 낸다. 표본이 3개보다 적으면 막대 없이 경과만 보인다 | 본체를 고치지 않고 이미 있는 값으로 된다. 표본이 적으면 막대가 거짓말을 한다 |
| 경과가 평소를 넘으면 막대를 가득 채우고 "평소보다 길다"를 옅은 경고색 글로 적는다 | 실패가 아니므로 실패 색을 쓰지 않는다 |
| 경과 시간은 batch나 머지 뒤 검사가 돌 때만 1초마다 다시 그린다. 프로세스는 더 띄우지 않는다 | 진행 막대가 멈춰 보이지 않게 하되 poll 정책은 그대로 둔다 |
| toast는 멈춤, 머지 뒤 검사 실패, 승인 대기, 사람 차례가 **새로 생길 때** 한 번 띄운다 | 사람 차례는 요청에 없지만 승인 대기와 같은 "사람이 손쓸 일"이다. 같은 항목으로 반복해서 띄우지 않는다 |
| mod가 뜬 뒤 첫 읽기에서 이미 있던 문제는 toast하지 않는다 | Herdr를 다시 켤 때마다 지난 문제가 쏟아지지 않게 한다. 패널에는 그대로 보인다(8절 결정 2) |
| 사이드바 space 배지는 만들지 않는다. macOS에서는 `setBadge`로 앱 아이콘에 손쓸 일 수를 단다 | mod가 space 배지를 정하는 API가 없다(3절). `setBadge`는 Linux에서 아무 일도 하지 않지만 Herdr가 지원하는 방법이다 |
| 로그·보고서는 chute mod 자신을 `openOverlay` 창으로 띄워 읽기 전용으로 보여 준다 | files mod는 밖에서 파일을 열라는 명령을 받지 않는다. 창은 레이아웃을 바꾸지 않고, 원격 허브의 파일도 `readTextFile(path, {on})`로 읽는다 |
| 최근 머지를 누르면 `https://github.com/<slug>/pull/<번호>`를 `cx.open_url`로 연다. slug가 `소유자/이름` 꼴이 아니면 누를 수 없게 둔다 | chute는 `gh`로 GitHub를 다룬다. 이상한 slug로 엉뚱한 주소를 열지 않는다 |
| 오늘을 펼쳤는지는 저장소마다 `localStorage`에 기억한다 | 15초마다 다시 읽어도 접힘이 풀리지 않게 한다 |
| 오늘 통계 칸에 있던 "머지 뒤 검사 마지막 통과"는 머지 뒤 검사 구역으로 옮긴다 | 통계가 아니라 상태다 |

## 6. 작업 나누기

작업 둘, 순차다.

| 작업 | 내용 | 방식 | 방식의 이유 |
|---|---|---|---|
| `status-feed` | chute 본체: `batch.steps`, history `merged`의 `title`, status의 `recent_merged`, 시험용 fixture | `poteto` | 상태 파일(`state.json`의 batch)과 history 데이터 형식을 바꾼다 |
| `board-ux` (`after: status-feed`) | mod: 제안 1~8과 디자인 전부 | `basic` | 화면 작업이다. 머지·상태 저장·잠금을 건드리지 않고 `status` 출력을 읽기만 한다 |

순차인 이유: `board-ux`가 `status-feed`의 새 필드를 쓰고, 두 작업이 `tests/fixtures/status-full.json`을 함께 본다(표의 "한쪽이 다른 쪽의 결과를 쓴다").

mod 작업은 한 작업으로 둔다. 제안 1~8이 모두 `main.js`의 같은 화면(저장소 구역)과 `board.js`의 같은 해석 함수를 다시 짜므로 나누면 순차가 되고 PR만 늘어난다.

## 7. 범위 밖

- 사이드바 space 옆 배지: Herdr에 mod용 방법이 없다. Herdr에 그런 API가 생기면 따로 한다.
- 사람 텍스트 출력(`chute status`의 글)에 단계 수나 최근 머지를 더하는 일.
- 머지 뒤 검사의 평소 시간(요청 제안 4에 없다).
- 반송 사건 외의 재시도(flaky 재실행 등)를 최근 머지에 표시하는 일.
- 사용자 Herdr 테마를 바꿔 라이트 테마를 찍는 일. 라이트 테마는 색 토큰만 쓰는 것으로 보장한다(작업 2의 성공 조건).
- 다른 Herdr mod, 레이아웃 파일, `seen.json`을 고치는 일.

## 8. 사용자가 정해야 하는 결정

1. **사이드바 배지가 없는 것을 받아들일지.** Herdr에는 mod가 space 옆 배지를 다는 방법이 없다. 이 플랜은 toast와 (macOS에서만 보이는) 앱 아이콘 배지로 대신한다. Linux에서는 toast만 남는다.
2. **Herdr를 켤 때 이미 있는 문제를 toast할지.** 기본은 하지 않는다(패널에만 보인다). 켤 때도 한 번 알리길 원하면 승인 때 말해 달라.
