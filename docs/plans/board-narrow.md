# 현황판 좁은 폭 플랜: 좁을 때 PR 줄의 시간과 아이콘을 제목 아래로 내린다

> 작성일 2026-11-18. 플랜 에이전트가 쓴 설계다. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 1. 사용자가 풀려는 문제

현황판 패널을 좁게(약 300px) 두면 PR 줄의 제목이 한 줄에 3~5글자로 쪼개져 줄이 세로로 길어진다. 사용자가 본 화면에서 CURRENT BATCH의 #536 "현황판 커넥터 API의 남은 결함을 고친다"가 5줄, RECENT의 #535·#534도 그렇다.

원인은 `mod/chute/main.js`의 `gridRow`(main `cd49c1b` 기준 967행)다. board-rows(`docs/plans/board-redesign.md` 3.5절)가 만든 격자는 줄마다 고정 폭 칸을 가로로 둔다.

| 칸 | 폭 |
|---|---|
| 순번 | 18 (순번이 없는 줄도 빈 칸) |
| PR 번호 | 최소 40 |
| 오른쪽 묶음 | 시간 최소 44 + 아이콘 20 × 2 + 사이 2 × 2 = 88 |
| 칸 사이 | 6 × 3 |

여기에 패널 테두리와 본문 여백(1 × 2 + 12 × 2), 줄 여백(6 × 2), 배치 면 여백(10 × 2)을 빼면 300px 패널의 배치 줄에서 제목 칸은 약 78px(한글 6자 안팎)다. RECENT 줄은 약 98px다. 오케스트레이터가 짚은 원인이 코드와 맞다.

## 2. 확정된 결정

요청에 적힌 것이다.

| 번호 | 결정 |
|---|---|

| 4 | PR 하나로 끝낸다 |

## 3. 스스로 정한 결정

### 3.1 폭을 아는 방법

| 결정 | 이유 |
|---|---|
| 루트 요소(`render`의 `frame`, id `chute`)에 `on_size_change((size, cx) => …)`를 달아 너비를 받는다 | 설치된 안내(`~/.config/herdr-app/AGENTS.md`의 "Size", `gpui-kit.d.ts`의 `on_size_change`)가 이 방법을 적는다. 첫 배치 뒤와 크기가 바뀔 때마다 논리 픽셀 `{width, height}`를 준다. `props()`에는 크기가 없다. CSS 컨테이너 질의 같은 것은 gpui-kit에 없다 |
| 받은 너비로 "좁음" 여부만 인스턴스에 두고, 그 값이 바뀔 때만 `cx.notify()`를 부른다 | 매번 다시 그리면 크기 변화마다 쓸데없이 그린다. 좁음 여부가 같으면 화면도 같다 |
| 크기를 아직 모르면(첫 배치 전, `herdr-app check`) 넓은 모양으로 그린다 | 지금 모습이 기본값이 된다 |
| 판정은 `board.js`의 순수 함수 `isNarrow(width)`와 상수 `NARROW_WIDTH`로 둔다. 너비가 유한한 수이고 `NARROW_WIDTH`보다 작을 때만 참이다 | 경계값을 `board.test.js`에서 시험할 수 있다. `main.js`는 시험이 없다 |
| `NARROW_WIDTH`는 340에서 시작한다. 기본 패널(`mod.json`의 `size` 360)은 넓은 모양, 300px 패널은 좁은 모양이어야 하고, 격리 창에서 360 패널의 루트 너비가 340보다 작게 나오면 300 패널이 좁은 모양을 지키는 범위에서 낮춘다 | 기본 크기의 모습을 바꾸지 않는 것이 결정 2다. 넓은 격자는 340px에서 배치 줄 제목 칸이 약 118px(한글 9자 안팎)라 그보다 좁으면 좁은 모양이 낫다. 패널 틀이 먹는 폭은 실제 창에서만 잴 수 있다 |

### 3.2 좁은 모양

| 결정 | 이유 |
|---|---|
| 좁을 때 `gridRow`의 오른쪽 묶음(시간 칸 + 아이콘 자리 둘)을 제목 아래 줄로 내린다. 그 줄은 제목 칸에 맞춰 들여 쓰고, 왼쪽에 칩(지금 `chipRow`, 줄바꿈 허용, 남는 폭), 오른쪽 끝에 오른쪽 묶음을 그대로 둔다. submitter 줄은 그 아래 지금처럼 | 오른쪽 묶음이 88px로 가장 크다. 묶음째 옮기면 시간 칸과 `≡`·`↗` 자리가 줄 오른쪽 끝에 같은 세로줄로 남아 줄끼리 정렬이 유지된다. 요청의 첫 예다 |
| 좁을 때 순번이 없는 줄(배치, 반송, 최근, 알 수 없는 상태)은 빈 순번 칸을 두지 않는다. 순번이 있는 대기 줄은 순번 칸을 지킨다 | 빈 칸과 칸 사이로 24px를 돌려받는다. 순번이 있고 없는 줄은 다른 구역이라 구역 사이 PR 번호 세로줄이 어긋나는 것은 좁은 폭에서 받아들인다 |
| 좁을 때 아랫줄은 칩이 없어도 그린다. 오른쪽 묶음의 빈 자리(빈 시간 칸, 빈 아이콘 자리)도 넓을 때처럼 지킨다 | 모든 줄이 아랫줄 오른쪽 끝에 같은 묶음을 가져야 `↗`가 줄마다 같은 세로줄에 선다. 칩 없는 최근 줄도 시간과 아이콘이 있어 빈 줄이 되지 않는다 |
| PR 번호를 제목 위로 올리지 않는다 | 40px를 더 얻는 대신 모든 줄이 한 줄씩 늘어난다. 위 두 결정으로 목표 폭을 넘는다 |
| 넓을 때 `gridRow`의 결과는 지금과 같다 | 결정 2 |

좁은 모양의 제목 칸(300px 패널): 배치 줄 약 196px, 최근·반송 줄 약 216px, 대기 줄 약 192px. 한글 13px 기준 14자 이상이다.

### 3.3 건드리지 않는 곳

| 결정 | 이유 |
|---|---|
| 사람 차례 카드의 `titleLine`은 바꾸지 않는다 | 시간 칸이 비고 아이콘 둘만 있어 300px에서 제목 칸이 약 158px(한글 12자 안팎)다. 요청의 목표를 이미 넘는다 |
| 배치 머리, 단계 막대, 숫자 칸, POST-MERGE 줄, 경고 카드는 바꾸지 않는다 | 사용자가 본 문제는 PR 줄의 제목이다. 이 줄들은 `truncate`나 줄바꿈으로 이미 좁은 폭을 견딘다 |
