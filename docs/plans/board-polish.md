## 1. 사용자가 풀려는 문제

사용자는 현황판 mod(`mod/chute/`)를 쓰다가 "각 데몬 이름을 접었다가 펼쳤다가 할 수 있는 기능은? 조금 더 uiux 개선하고 싶은데 먼저 니가 제안해줘"라고 했다. 오케스트레이터가 제안 1~8과 목업을 보였고 사용자는 "모두 적용하자."라고 했다. 그 뒤 board-en을 설치한 실제 화면(`/home/dev/.claude/jobs/3924a6bb/tmp/board-en-live.png`)에서 결함 하나가 더 보였고, 오케스트레이터가 플랜에 넣으라고 했다(제안 9로 적는다).

지금 현황판(main `e8b02fd`, board-en 머지 뒤 기준)은 이렇다.

- 접기는 머리의 `▾` 하나로 **모든 저장소를 한꺼번에** 한 줄로 줄이는 것뿐이다(`main.js` `fold`, localStorage `chute.folded`). 저장소마다 접을 수 없다.
- 저장소는 `chute status --json --all`이 준 순서대로 보인다. 문제 있는 저장소가 아래에 묻힐 수 있다.
- 최근 머지는 status가 주는 5건을 모두 보인다.
- 상태 점은 늘 정지해 있다. batch 구역의 글자 spinner만 움직인다.
- PR 줄 가운데 최근 머지와 반송 줄만 누를 수 있고, 무엇이 열리는지 보이지 않는다.
- 탭 막대의 `● chute` 버튼(사용자 개인 mod `tabs-chute`, 저장소 밖)은 패널이 열렸는지만 보이고 chute 상태는 모른다.
- 머리 줄은 `chute`라는 글자와 버튼뿐이다.
- 저장소 사이를 1px 선으로 나누고, 구역 제목과 숫자의 크기·정렬이 구역마다 조금씩 다르다.
- `Today` 줄(`9 merged · 1 bounced · median 4m`)이 좁은 패널에서 `median…`, `median 4…`로 잘린다. `main.js` `todayView`가 `board.js` `todayOf`의 `line` 한 문자열을 한 줄에 `truncate`로 그리기 때문이다. 가장 쓸모 있는 숫자인 중앙값이 먼저 사라진다.

`board-en`(mod 문구 영어화, 정상 색 초록, PR 번호 줄바꿈, 제목 없음 줄)은 PR #61로 main에 머지됐다(`e8b02fd`). 이 플랜은 그 위에서 시작한다. 아래 문구와 목업은 영어 화면 기준이고, 용어는 `docs/plans/board-en.md` 3.1절을 따른다.

## 4. 스스로 정한 결정과 그 이유

### 4.1 저장소별 접기 (제안 1)

| 결정 | 이유 |
|---|---|
| 저장소의 머리 줄을 하나로 합친다: `▾/▸` · 이름 · (허브 칩) · 빈칸 · 상태 점 · 상태 한 줄. 펼침과 접힘이 같은 줄이고, 펼치면 그 아래에 구역이 붙는다. 상태 한 줄은 넘치면 말줄임하고 tooltip에 전체 문구를 둔다 | 접을 때 줄이 바뀌지 않아 눈이 따라가기 쉽다. 목업이 이 모양이다. 지금은 펼친 화면은 이름과 상태가 두 줄, 접힌 화면은 한 줄이라 모양이 다르다 |
| 머리 줄 전체가 접기 단추다(hover 배경). 이름의 tooltip(`slug · 승인 방식`)은 그대로 둔다 | 작은 `▾`만 누르게 하면 좁은 패널에서 맞히기 어렵다 |
| 사용자의 선택은 localStorage `chute.fold.<repo id>`(`"1"`이면 접힘)에 저장소마다 둔다. 옛 전체 접기 키 `chute.folded`는 읽지 않고 지운다 | 저장소마다 기억하라는 요청이다. 같은 방식(`remember`/`recall`)이 이미 "Today" 펼침에 쓰인다 |
| 전체 접기 모드(`this.folded`, `foldedRepo`)는 없앤다. 머리의 `▾` 단추와 `<mod>.fold` 명령은 "모두 접기/모두 펼치기"가 된다. 펼친 저장소가 하나라도 있으면 모두 접고, 아니면 모두 펼친다. tooltip은 `Collapse all` / `Expand all` | 접힘 상태가 두 겹(전체·저장소)이면 무엇이 왜 접혔는지 알기 어렵다. 키 바인딩(`<mod>.fold`)을 쓰는 사람이 있어도 같은 명령으로 비슷하게 동작한다 |
| 자동 펼침은 **잠시 펼침**이다. 저장소마다 "문제 키" 집합을 두고, 사용자가 접어 둔 저장소에 이전 읽기에 없던 키가 생기면 화면에서만 펼친다(저장한 선택은 접힘 그대로). 그 저장소의 문제 키가 모두 사라지면 다시 접힌다. 잠시 펼친 사이 사용자가 머리 줄을 누르면 잠시 펼침이 끝나고 사용자의 선택이 된다 | 문제가 풀리면 사용자가 원래 원한 모양으로 돌아간다. 같은 문제로 다시 접은 저장소는 새 문제가 생기기 전까지 다시 열리지 않는다 |
| 문제 키는 그 저장소의 알림 키(`notices`의 `key`: 멈춤, 머지 뒤 실패, 승인 대기, 사람 차례)에 데몬 꺼짐(`daemon:off`)을 더한 것이다. 허브에 닿지 않음은 넣지 않는다 | 요청이 든 네 가지에 사람 차례를 더했다. 사람 차례도 손쓸 일이다. 알림 키는 이미 PR·HEAD·사유로 구별되어 "새 문제"를 가려낸다. 허브 끊김은 현황판에서 할 일이 없고 원격 허브가 오락가락하면 계속 열렸다 닫힌다. 접힌 줄에도 빨간 `Hub unreachable`이 보인다 |
| 처음 읽을 때(이전 키가 없을 때) 문제가 있으면 그 키는 새 키로 본다 | 현황판을 켰을 때 이미 사람 차례인 저장소가 접혀 있으면 안 된다 |
| 잠시 펼침의 계산은 `board.js`의 순수 함수(예: `nextFold(prev, keys)` → `{ folded, auto, keys }`)로 두고 `node --test`로 본다. `main.js`는 그 결과만 그린다 | 상태 전이가 여러 갈래라 시험으로 고정해야 한다 |

### 4.2 문제 우선 정렬 (제안 2)

| 결정 | 이유 |
|---|---|
| 등급은 상태 한 줄의 `tone`(board-en 뒤 `toneToken`이 색으로 바꾸는 그 값)에서 나온다. `error`(허브 끊김, 멈춤, 머지 뒤 실패, 데몬 꺼짐)와 `human`(사람 차례·승인 대기)이 0, `working`이 1, `waiting`이 2, `ok`가 3이다. 등급만으로 안정 정렬한다 | 상태 한 줄이 이미 board-ux 4.2의 우선순위로 저장소 하나의 가장 급한 일을 고른다. 같은 판단을 두 번 하지 않는다 |
| 같은 등급 안에서는 status가 준 순서를 지킨다. 다른 기준(이름, 시각)을 더하지 않는다 | 요청대로 깜빡이며 순서가 바뀌지 않게 한다 |
| 정렬은 `board.js`의 `interpret` 결과에서 한다(`board.repos`가 정렬된 채 나온다) | 시험할 수 있고, 알림·배지 계산은 순서와 무관하다 |

### 4.3 최근 머지 (제안 3)

| 결정 | 이유 |
|---|---|

| 펼침은 저장하지 않는다(창을 다시 열면 3건) | 잠깐 더 보는 동작이다. 저장 키를 늘리지 않는다 |

### 4.4 상태 점 움직임 (제안 4)

| 결정 | 이유 |
|---|---|
| 저장소에 batch가 있거나 머지 뒤 검사가 도는 중이면(`postVerify.run`) 머리 줄의 상태 점에 gpui-kit `loop("opacity", { from: 1, to: 0.35, period: 1600 })`를 건다. 아니면 정지 | gpui-kit의 `loop`는 네이티브로 약 30fps, 화면에 그려질 때만 돌고 `render`를 부르지 않는다(`gpui-kit.d.ts`). poll과 `tick`은 그대로다 |
| "도는 중" 판정은 `board.js`가 저장소마다 `active` 불리언으로 낸다 | 시험할 수 있게 한다 |
| 머지 뒤 검사만 도는 중이면 상태 한 줄은 그대로(`All clear`)이고 점만 깜빡인다 | 상태 한 줄의 우선순위는 board-ux·board-en에서 정했다. 바꾸지 않는다(7절 5번) |
| batch 구역의 글자 spinner는 그대로 둔다 | 이미 `frames`로 네이티브로 돈다 |
| `herdr-app check`가 `loop`를 받지 못하면 점 대신 `frames(["●","○"], 800)`류의 글자 깜빡임을 쓰고 보고서에 적는다 | 요청이 대안을 보고하라고 했다. `frames`도 `render`를 부르지 않는다 |

### 4.5 행 hover와 바로가기 (제안 5)

| 결정 | 이유 |
|---|---|
| PR이 있는 한 줄짜리 행(최근 머지, 대기, 반송, 현재 batch의 PR)은 hover 배경(`t.hover`)을 둔다. 사람 차례 카드는 카드 모양 그대로 두고 제목 줄 오른쪽에만 `↗`를 둔다 | 카드는 이미 테두리와 단추가 있어 행 hover가 어색하다 |
| 오른쪽 끝에 PR 열기 `↗`(tooltip `Open #421 on GitHub`)를 둔다. URL은 `board.js`의 `pullUrl(slug, pr)`로 만든다. slug가 없어 URL이 없으면 `↗`를 두지 않는다 | 요청의 `PR ↗`다. 지금 `›` 화살표는 무엇이 열리는지 말하지 않는다 |
| 보고서나 로그 경로가 status에 있는 행에만 `log`(tooltip `Open report` 또는 `Open log`)를 `↗` 왼쪽에 둔다. 지금은 반송 행의 보고서뿐이다. 최근 머지는 status에 보고서 경로가 없으므로 `log`를 두지 않는다(경로를 추측하지 않는다) | 없는 파일을 열지 않는다. status에 경로를 더하는 것은 본체 일이다(6절) |
| 행 자체를 누르는 동작은 지금 그대로다(최근 머지 → PR, 반송 → 보고서). 다른 행은 행을 눌러도 아무 일도 없고 아이콘만 누른다. 아이콘의 click은 `cx.stop_propagation()`으로 행에 닿지 않게 한다 | 익숙한 동작을 바꾸지 않는다. GPUI는 바깥 행의 handler도 부른다(`gpui-kit.d.ts` `stop_propagation`) |
| 아이콘은 글자(`↗`, `log`)로 그린다. svg 파일을 더하지 않는다 | `chute install`은 `main.js`, `board.js`, `mod.json`만 설치한다(`src/cmd/install.rs`). 파일을 더하면 본체를 고쳐야 한다 |
| 경고 카드의 `Report ›`·`Log ›` 단추와 사람 차례 카드의 보고서 경로 줄은 그대로 둔다 | 카드 안의 큰 단추가 이미 그 역할을 한다 |

### 4.6 탭 막대 버튼에 내보내는 값 (제안 6)

키는 `chute.status`, 값은 다음 모양이다.

```js
setShared("chute.status", {
  grade: "ok" | "running" | "attention" | "failed",
  issues: 0,      // 손쓸 일의 수 (아래)
  running: 0,     // grade가 running인 저장소 수
  repos: 2,       // 보이는 저장소 수
  since: 1794723600000, // 이 값(grade·issues·running·repos)이 처음 나온 시각, ms
});
```

| 결정 | 이유 |
|---|---|
| 전체 `grade`는 저장소 등급 가운데 가장 급한 것이다. 상태 한 줄 `tone`이 `error`인 저장소가 있으면 `failed`, 아니면 `human`이 있으면 `attention`, 아니면 `working`이나 `waiting`이 있으면 `running`, 아니면 `ok` | 4.2와 같은 판단을 쓴다. 요청이 준 값은 넷이라 대기(`waiting`)를 `running`에 넣었다. 큐에 PR이 있으면 일이 진행 중이다(7절 1번) |
| `status`를 읽지 못했거나(`failed`) chute를 실행할 수 없으면(`missing`) `{ grade: "failed", issues: 1, running: 0, repos: 0 }`. 저장소가 없으면(`empty`) `ok`와 0들. 불러오는 중에는 내보내지 않는다(이전 값 유지) | 버튼이 "읽을 수 없음"을 실패로 보이게 한다 |
| `issues`는 손쓸 일의 수다. 저장소마다 사람 차례 카드 수 + `tone: "error"`인 경고 카드 수(멈춤, 데몬 꺼짐, 머지 뒤 실패) + 허브에 닿지 않으면 1을 더한다. `tone: "warn"` 경고(설정 읽기 실패 따위)는 세지 않는다 | `grade`를 `failed`나 `attention`으로 만드는 것만 센다. 둘이 어긋나면 버튼의 점과 숫자가 서로 다른 말을 한다 |
| 값은 `grade`·`issues`·`running`·`repos` 가운데 하나라도 바뀔 때만 `setShared`한다. `since`는 그때의 시각이다 | `setShared`는 모든 mod를 다시 그린다(`gpui-kit.d.ts`). 15초·5초마다 쓰면 창 전체가 그만큼 다시 그려진다 |
| 오버레이 사본과 `checking()` 중에는 쓰지 않는다(배지·알림과 같은 조건). mod가 닫히면(View의 `close`) `null`을 쓴다 | 사본이 둘이면 서로 덮는다. 값은 저장되어 남으므로(`shared`는 persisted) mod가 없는데 옛 등급이 남지 않게 한다 |
| 머리 줄 요약(4.7)과 이 값은 `board.js`의 같은 순수 함수(예: `overview(board)`)에서 나온다 | 머리 줄과 탭 버튼이 같은 숫자를 보인다. 시험으로 고정한다 |

`tabs-chute`가 할 일(오케스트레이터 몫, 이 저장소 밖): `shared("chute.status")`를 읽어 버튼 점 색을 `failed` → `t.ansi1`, `attention` → `t.blocked`, `running` → `t.working`, `ok` → `t.ansi2`(board-en의 정상 색)로, 값이 `null`이거나 없으면 지금처럼 그린다. `issues > 0`이면 숫자를 붙일 수 있다.

### 4.7 머리 줄 요약 (제안 7)

| 결정 | 이유 |
|---|---|
| `chute` 옆에 `2 repos · 1 running · 0 issues`를 흐린 작은 글로 둔다. 단수는 `1 repo`, `1 issue`. `issues`가 0보다 크면 그 부분만 `failed`면 `t.ansi1`, `attention`이면 `t.blocked` | 위 4.6과 같은 숫자다. 문제 수만 색으로 눈에 띄게 한다 |
| 오른쪽에 마지막 새로 고침 시각을 `12:04`(현지 시각 시:분)로 둔다. tooltip은 `Updated 2026-11-17 12:04:31`. 시각은 `status` 읽기가 끝난 때다 | 상대 시각("12s ago")은 매초 다시 그려야 하는데, 지금 `tick`은 진행 중일 때만 다시 그린다. 시:분은 읽을 때만 바뀐다 |
| 폭이 모자라면 요약 글이 먼저 말줄임된다. 시각, `▾`, `✕`는 줄지 않는다 | 368px에서 단추가 밀려나지 않게 한다 |
| 오버레이 사본의 머리 줄에도 같은 요약을 둔다 | 같은 화면이다 |

### 4.8 간격과 글자 위계 (제안 8)

### 4.9 `Today` 줄 잘림 (제안 9)

| 결정 | 이유 |
|---|---|
| `todayOf`는 한 문자열 `line` 대신 조각 목록 `parts`(예: `["9 merged", "1 bounced", "median 4m"]`)를 낸다. `main.js`는 조각마다 줄바꿈하지 않는 글로 그리고 사이에 `·`를 두며, 줄은 `flex_wrap`이라 폭이 모자라면 **조각 단위로** 다음 줄로 넘어간다. 말줄임(`truncate`)은 쓰지 않는다 | 두 줄로 보이는 쪽을 골랐다. 낱말을 줄이면(`4m med`) 뜻이 흐려지고, 그래도 더 좁은 폭에서는 또 잘린다. 조각 단위로 넘기면 숫자가 반쯤 잘리는 일이 없다 |
| 접기 화살표(`›`/`⌄`)는 첫 줄 오른쪽 끝에 붙어 있고, 줄 전체를 누르면 펼쳐지는 동작은 그대로다 | 두 줄이 되어도 누르는 곳이 바뀌지 않는다 |
| 시험은 `todayOf`의 `parts`(값이 없을 때 `—`, 단수·복수)와, 368px 폭에서 줄이 잘리지 않는 것은 캡처가 되면 캡처로, 안 되면 보고서에 그 사실을 적는다 | 폭은 `node --test`로 볼 수 없다 |

### 4.10 작업 나누기

| 작업 | 내용 | 방식 | 방식의 이유 |
|---|---|---|---|
| `board-polish` | 제안 1~9 전부, 시험, README "현황판 읽기"에 한 문단 | `basic` | 화면 조정이다. 머지·상태 저장·잠금을 건드리지 않고 `status` 출력을 읽기만 한다. `chute.status`는 다른 mod에 값을 보이는 것뿐이다 |

작업을 하나로 둔 이유: 아홉 제안이 모두 `main.js`의 저장소 그리기(`repoView`, 머리 줄, 구역 제목, 행)와 `board.js`의 `interpret` 결과를 함께 고친다. 나누면 같은 함수를 여러 작업이 다시 짜야 해서 순차가 되고, 사용자 주간 사용량(90%대)에 작업마다 드는 비용이 더해진다. 작업이 하나라 병렬·순차 관계는 없다.

`board-en`은 이미 main에 있으므로(`e8b02fd`) 기다릴 작업이 없다.

README "현황판 읽기"에 더할 한 문단: 저장소 머리 줄을 눌러 접고 펼친다, 접어 둔 저장소도 손쓸 일이 생기면 잠시 펼쳐진다, 문제 있는 저장소가 위로 온다, 다른 mod는 `chute.status`(4.6의 모양)를 읽을 수 있다. 다른 mod가 기댈 값이라 설명서에 적는다.

## 5. 고치는 곳과 건드리지 않는 곳

- 고친다: `mod/chute/main.js`, `mod/chute/board.js`, `mod/chute/board.test.js`, `README.md`의 "현황판 읽기".
- 고치지 않는다: chute 본체(`src/`), `mod/chute/mod.json`, `tests/fixtures/status-full.json`, 탭 막대 mod `tabs-chute`, 다른 Herdr mod, 사용자의 `~/.config/herdr-app/` 아래 파일.
- mod 폴더에 새 파일을 더하지 않는다(4.5).

## 6. 범위 밖

- 최근 머지를 5건보다 많이 보이는 것. 본체 `RECENT_MERGED`를 늘리는 일이다.
- 최근 머지 줄의 `log`. status의 `recent_merged`에 보고서·로그 경로가 없다. 본체가 경로를 더해야 한다.
- `tabs-chute`의 버튼 색 수정. 오케스트레이터가 4.6의 값을 읽어 고친다.
- 상태 한 줄의 우선순위와 문구(board-ux·board-en에서 정함), 알림(toast)과 배지 규칙.
- 키 바인딩 추가, 패널 폭·위치(`mod.json`) 변경.

## 7. 사용자가 정해야 하는 결정

1. **대기만 있을 때의 탭 버튼 색.** 이 플랜은 큐에 PR이 있고 검증은 안 도는 상태(`Queued · 3`, CI 대기 포함)를 `running`으로 내보낸다. "검증이 실제로 돌 때만 running"을 원하면 `ok`로 바꿀 수 있다.
2. **문제가 풀린 뒤의 자동 펼침.** 이 플랜은 문제가 모두 사라지면 다시 접는다. 펼친 채 두길 원하면 말해 달라.
3. **최근 머지의 `+ N more` 상한.** status가 5건만 주므로 목업의 `+ 7 more`는 나오지 않고 많아야 `+ 2 more`다. 더 많이 보려면 본체 작업을 따로 연다.
4. **전체 접기 모드를 없애는 것.** 머리의 `▾`는 "모두 접기/모두 펼치기"가 된다. 옛 전체 접기 상태(`chute.folded`)는 이어지지 않는다.
5. **머지 뒤 검사만 도는 중의 표시.** 점은 깜빡이지만 상태 한 줄은 `All clear`다. 상태 한 줄에도 `Post-merge check · e2e`처럼 보이길 원하면 상태 한 줄 우선순위를 바꾸는 결정이 필요하다.
6. **새로 고침 시각.** 상대 시각 대신 `12:04`처럼 시:분으로 보인다(매초 다시 그리지 않으려고).
